1. Executive Summary

AdMu (Advertisement Mu) is a fully developed and deployed B2B SaaS platform that provides independent chiropractic and physical therapy clinics in Japan with an easy-to-use advertising management dashboard. The tool is live and serving clients at https://admu-backend-jxi0.onrender.com.

Current Status: AdMu is a completed, production-deployed tool with a fully functional backend, frontend dashboard, multi-tenant architecture, authentication system, and automated monitoring. The tool is currently operating in mock-data mode while awaiting API token approval — the only remaining step before connecting to live Google Ads data.

What AdMu does:

  • Reads campaign performance data (impressions, clicks, cost, conversions) from each clinic's Google Ads account via the official SDK
  • Displays the data in a simplified dashboard designed for non-technical clinic owners
  • Uploads offline conversions (patient inquiry form submissions captured by gclid) back to Google Ads to measure real-world patient acquisition
  • Generates AI-powered ad copy suggestions and negative keyword recommendations

What AdMu does NOT do:

  • Does NOT create or modify campaigns, ad groups, or ads programmatically
  • Does NOT perform automated bidding or budget changes via the API
  • Does NOT access any personally identifiable information (PII) of ad viewers

3.2 Example GAQL Queries

-- Campaign performance (dashboard)
SELECT campaign.id, campaign.name, campaign.status,
       campaign_budget.amount_micros,
       metrics.impressions, metrics.clicks, metrics.ctr,
       metrics.average_cpc, metrics.cost_micros,
       metrics.conversions, metrics.conversions_from_interactions_rate
FROM campaign
WHERE segments.date DURING LAST_7_DAYS

-- Daily performance trend
SELECT segments.date, metrics.impressions, metrics.clicks, metrics.ctr,
       metrics.average_cpc, metrics.cost_micros, metrics.conversions,
       metrics.conversions_from_interactions_rate
FROM campaign
WHERE segments.date DURING LAST_30_DAYS
ORDER BY segments.date

-- Search term analysis (negative keyword detection)
SELECT search_term_view.search_term,
       campaign.id, campaign.name,
       metrics.clicks, metrics.cost_micros, metrics.conversions
FROM search_term_view
WHERE segments.date DURING LAST_30_DAYS
  AND metrics.impressions > 0
ORDER BY metrics.cost_micros DESC
LIMIT 500

3.3 Offline Conversion Upload Flow

  1. Patient visits the clinic's website via a Google Ads click → gclid is captured in the URL
  2. Patient submits an inquiry form → gclid + form data are stored in AdMu's database
  3. AdMu backend calls ConversionUploadService.UploadClickConversions to send the conversion back to Google Ads
  4. The conversion appears in the clinic's Google Ads reports as an offline conversion, enabling accurate ROI measurement

3.4 Data Retrieved and Storage

  • Data accessed: Campaign/keyword aggregate metrics only (impressions, clicks, cost, conversions). No PII of ad viewers is accessed.
  • Storage: Metrics are stored in PostgreSQL for up to 90 days for trend analysis, then automatically purged.
  • Data isolation: Each clinic's data is isolated by clinic_id (tenant key). Cross-tenant access is prevented at the application layer.

5. User Workflow

  1. Signup: Clinic owner registers on AdMu. Account is created in "pending" state until admin approval.
  2. Admin Approval: AdMu administrator reviews and activates the account. Welcome email is sent automatically.
  3. OAuth Connection: Clinic owner connects their Google Ads account via standard Google OAuth 2.0 consent screen. AdMu receives a refresh token, which is AES-256 encrypted before storage.
  4. Dashboard: On each visit, AdMu calls the Google Ads API (SearchStream/GAQL) using the stored refresh token to fetch campaign metrics. Data is displayed as interactive charts and KPI cards.
  5. Monitoring: Background scheduler continuously monitors campaign health and sends alerts via LINE and email when anomalies are detected.
  6. Offline Conversion: When a patient submits an inquiry form on the clinic's website, the captured gclid is sent to Google Ads as an offline conversion.

6. Security & Credential Management

6.1 Authentication & Authorization

Security FeatureImplementation
Session ManagementJWT stored in HttpOnly, Secure, SameSite=Lax cookies. No localStorage token storage.
CSRF ProtectionDouble Submit Cookie pattern. All mutating API calls require X-CSRF-Token header matching the csrf_token cookie.
Rate Limiting120 requests/minute per IP (general API), 3 requests/5 minutes for contact forms (bot protection).
Multi-tenant IsolationMiddleware validates clinic_id in every API request against the authenticated user's assigned clinic. Cross-tenant access returns HTTP 403.
Role-based AccessTwo roles: admin (full system access) and user (clinic-scoped access only).

6.2 Credential Security

CredentialProtection Method
OAuth Refresh TokensAES-256-CBC encrypted at rest in PostgreSQL. Encryption key stored as server-side environment variable (ENCRYPTION_KEY).
Developer TokenStored as server-side environment variable (MASTER_ADS_DEVELOPER_TOKEN). Never exposed to frontend.
Client SecretAES-256 encrypted in database. Decrypted only in server memory during API calls.
User Passwordsbcrypt hashed (no plaintext storage).

6.3 Security Headers

  • Content-Security-Policy — Restricts script/style sources to trusted CDNs only

  • X-XSS-Protection: 1; mode=block

8. Compliance & Data Handling

  • No PII: Only aggregate advertising metrics are accessed from the Google Ads API. No end-user personal data is retrieved.
  • Data Minimization: Only the specific fields required for dashboard display are requested via GAQL SELECT statements.
  • Retention Policy: Performance metrics are retained for 90 days for trend analysis, then automatically purged. Audit logs and alerts are purged after 365 days.
  • Tenant Isolation: Each clinic's data is stored with a clinic_id foreign key. Cross-tenant access is prevented at both the middleware and database query levels.
  • Google API Terms Compliance: AdMu does not resell raw Google Ads data. Data is used solely to generate the in-app dashboard for each account owner.
  • OAuth Consent: Each clinic owner explicitly grants access via Google's standard OAuth consent screen before any data is read.
  • Token Revocation: Clinic owners can disconnect their Google Ads account at any time from the settings page, which deletes the stored refresh token.

1. Product Overview

AdMu (Advertisement Mu) is a B2B SaaS platform purpose-built for independent chiropractic and physical therapy clinics in Japan. It provides a unified, easy-to-use dashboard that aggregates Google Ads performance data (impressions, clicks, costs, and conversions) so that clinic owners — who are typically non-technical — can monitor their advertising ROI without needing direct access to the Google Ads console.

Each clinic subscribes to AdMu on a monthly basis. The platform is multi-tenant: each tenant (clinic) connects their own Google Ads account via OAuth 2.0, and their data is isolated and never shared across tenants.

2. How the Tool Uses the Google Ads API

2.1 Purpose of API Usage

AdMu uses the Google Ads API exclusively to read campaign performance metrics on behalf of each clinic's linked Google Ads account. No data is ever written back to Google Ads. No automated bidding, ad creation, or campaign modification is performed.

2.3 Data Retrieved and How It Is Used

  • Campaign impressions, clicks, cost, conversions (aggregate metrics only — no PII)
  • Date-range segmented data (daily, weekly, monthly) for trend charts
  • Data is displayed in the AdMu dashboard and stored temporarily in a PostgreSQL database for up to 90 days for trend analysis
  • No personally identifiable information (PII) of ad audience users is accessed or stored

3.3 Credential Security

  • Each tenant's OAuth Refresh Token is AES-256 encrypted before storage in the database
  • Developer token is stored as a server-side environment variable — never exposed to the client
  • All communication is over HTTPS (TLS 1.3)
  • CSRF protection via Double Submit Cookie pattern
  • Security headers: CSP, HSTS, X-Frame-Options implemented

4. User Workflow

  1. Clinic owner signs up for AdMu and logs in via the admin dashboard
  2. Admin connects the clinic's Google Ads account via Google OAuth 2.0 consent screen
  3. AdMu backend exchanges the authorization code for an access token + refresh token
  4. On dashboard load, AdMu calls the Google Ads API using the stored refresh token to fetch campaign metrics
  5. Retrieved metrics are displayed as charts and KPI cards (impressions, clicks, cost, conversions, CTR, CPC)
  6. Offline Conversion Tracking (OCT): gclid values captured from the clinic website's patient inquiry forms are uploaded to Google Ads as offline conversions to measure phone/walk-in patient acquisition

5. Access Level Requested and Justification

Requested Access Level: Basic Access

Justification: AdMu serves multiple chiropractic clinic clients (tenants), each with their own Google Ads accounts. To fetch live campaign performance data for each client account via the official SDK, Basic Access (production developer token) is required. Test Account access only permits access to a single test account and cannot be used to serve real paying clients with their real account data. Basic Access is the minimum level required for this multi-tenant SaaS use case.

6. Compliance and Data Handling

  • No PII: Only aggregate advertising metrics are accessed; no end-user personal data is retrieved from Google Ads API
  • Data Minimization: Only the fields required for dashboard display are fetched via GAQL SELECT statements
  • Retention: Metrics are retained for 90 days for trend display, then purged automatically
  • Tenant Isolation: Each clinic's data is stored with a tenant_id key; cross-tenant access is prevented at the application layer
  • Google API Terms Compliance: AdMu does not resell raw Google Ads data; data is used solely to generate the in-app dashboard for each account owner
  • OAuth Consent: Each clinic owner explicitly grants access via Google's standard OAuth consent screen before any data is read
